# 苏格拉底功能重新设计 — 设计文档

- 日期：2026-05-28
- 范围：重做 Whetstone 的"考考我"（Socratic quiz）与打分机制
- 状态：设计已逐节确认，待写实现计划

## 目标

1. **可实操、可信的打分一致性**：同一用户对同一篇文章的理解不变时，多次测分应落在合理小区间（如 41/43/46），不应在 40/60/50 间大幅漂移。
2. **在锁住一致性的前提下保留灵活性**：兼顾不同长度/领域文章的深度与效率——既不冗长（问 40 个才出结果），也不肤浅（问 2 个就靠"幻觉"猜分）。

## 根因诊断

现状 quiz（`Prompts.socraticQuizSystem` + `socraticQuizUser`）让模型对整段对话做一次"整体打分"（`SCORE:` 一行，正则 `parseScore` 抓取）。整体主观判断在多次运行间会漂移，是不一致的根源。现状 quiz 还**完全没用**已提取的概念，AI 即兴出题。

修复方向：把"打分"从模型的整体主观判断里拿出来，拆成固定 rubric 的小单元，由代码聚合；提问流程改为概念驱动 + 有界的动态深度。

## 已确认的核心决策

| 维度 | 决策 |
|---|---|
| 打分机制 | 按概念逐项打分，代码聚合（模型不吐总分） |
| 评分维度 | 三维：复述 recall / 举例 apply / 辨析 analyze，权重 1/2/3 |
| 深度与打分关系 | 动态深入只为收集证据、提高打分把握，**不进分数** |
| 概念来源 | 复用已提取概念。提取数量：原设计 2~7；**实测后改为固定 3**（见末尾「实测调优」） |
| 流程呈现 | 连贯一问一答对话 + 低调进度（概念 N/M），末尾出总分 |
| 出分 UI | 专用 `QuizResultCard`（复刻 Concept hero card：cream + 1px 黑边 + 直角）：大号总分 + 每概念三维方块 ■/□（无强调色）+ 单概念 note + 底部总评 |
| 入口位置 | 从对话内 chip 移到 AI pane header 右上角的常驻正方形按钮（38px、cream 底、1px 黑边、直角、hover 反色）；图标 = 黑块头像剖面剪影 + 问号（零外部素材）；同一按钮兼做「再测一次」，删除 ConceptCard 内「考考我」chip |
| Library 分数 | 文章卡片**右下角**持久显示 `SCORE N`（数据已存于 `article.latestScore`，本次仅从左上移到右下） |
| 打分架构 | 导师对话 × N（常规温度）+ 独立评分员 × 1（temperature 0，结构化输出），代码聚合 |
| 深度上限 | 原设计：每概念最多 4 轮。**实测后改为每概念恰好 1 题**（单题覆盖三面），轮数封顶 = 概念数+2（见末尾「实测调优」） |

## 第 1 节：打分数学

每个维度评 3 档（评分员只做这个局部判断，不给总分）：

| 档位 | 含义 | 原始分 |
|---|---|---|
| 0 = 未展现 | 没说到 / 答错 / 没问到也算未展现 | 0 |
| 1 = 部分 | 方向对但不完整、含糊 | 1 |
| 2 = 充分 | 准确、到位 | 2 |

单概念得分（三维加权，权重体现"会背 ≠ 真懂"）：

```
复述 recall  权重 1
举例 apply   权重 2
辨析 analyze 权重 3
满分 = 2·1 + 2·2 + 2·3 = 12
概念分(%) = (recall·1 + apply·2 + analyze·3) / 12 × 100
```

文章总分 = 各概念分的算术平均（等权）：

```
总分 = round( Σ 概念分 / 概念数 )
```

算例（3 概念）：

```
概念A 复述2 举例2 辨析2 → 12/12 = 100
概念B 复述2 举例1 辨析0 →  4/12 =  33
概念C 复述1 举例1 辨析0 →  3/12 =  25
总分 = (100+33+25)/3 = 53
```

一致性来源：
1. 评分员永远不直接给总分，只对 N×3 个小项做 0/1/2 判断——小项判断比"整体几分"稳得多。
2. temperature 0 + 固定档位定义，同一份 transcript 重复评分基本同结果。
3. 单维偏差只动满分的 1/12，被平均稀释；要让总分漂 10+ 分需多维同时判错，概率低 → 对应"小区间波动可接受"。

边界规则：4 问封顶仍未问到某维 → 该维按 **0 = 未展现** 计。证据不足保守给分，不让评分员猜。

## 第 2 节：对话流程（两层框架 + 导师职责）

导师（Tutor）是有状态的对话角色，每轮一次调用，带历史。受"控制契约"约束：

**第一层 · 核心概念层（硬约束）**
- 必须覆盖全部概念，每个概念至少问 1 个问题（不可跳过）。
- 概念按提取顺序逐个走，问完一个再进下一个。

**第二层 · 动态延伸层（框架内自由）**
- 导师在每个概念上内部自查三维证据：复述/举例/辨析是否都拿到足够信号来判定。
- 信号不足 → 在同一概念上追问，每概念最多 4 问（含第 1 问）。
- 信号已足 → 立即收尾该概念，进下一个。简单概念可能只问 1 问，难概念问满 4 问。
- 导师不打分，只决定"问什么、问几个、何时转"。

**隐藏控制标记（给代码用，对用户隐藏，显示前剥除）**
- 转概念：`<<NEXT concept=3>>` → 驱动进度 `概念 3/5`
- 全部问完：`<<DONE>>` → 触发评分员

**苏格拉底约束（进导师 system prompt）**：不给答案、不剧透、一次一个问题、问题要戳理解盲区。

一轮数据流：

```
用户答 → 导师调用(历史 + 概念表 + 控制契约, 常规温度)
       → 回复含 1 个新问题 + 可能的 <<NEXT>>/<<DONE>> 标记
       → 代码剥标记、更新进度、显示问题
       → 见 <<DONE>> 则进入评分员
```

深度判断放在导师而非评分员：是否"够了、要不要再问"必须看用户上一句实时决定，是导师的活；评分员是最后对完整 transcript 算账。职责不重叠。

## 第 3 节：评分员（一致性的锚）

导师发 `<<DONE>>` 后，单独一次调用，与导师完全解耦。

**输入**
- 概念表（name + explanation）
- 完整对话 transcript（用户所有回答 + 导师所有问题）
- 固定 rubric（三维档位定义，写死在 system prompt）

**调用参数**
- `temperature = 0`（让同一 transcript 可复现）
- system prompt 钉死三维 0/1/2 判定标准 + 边界规则（未问到 = 0）

**输出（严格 JSON，复用 `stripFence` + 解析模式）**

```json
[
  {"concept":"Qubits","recall":2,"apply":1,"analyze":0,"note":"能复述定义，举例勉强，未触及与经典比特的本质区别"},
  {"concept":"Superposition","recall":2,"apply":2,"analyze":2,"note":"理解透彻"}
]
```

- `recall/apply/analyze` ∈ {0,1,2}，越界则该项归 0。
- `note`：每概念一句诊断，喂给最终展示。

**代码侧（不靠模型算总分）**
1. 解析 JSON → 校验 0/1/2、概念数对齐（多删少补，复用 translation 解析容错策略）。
2. 按第 1 节公式算每概念分 + 总分。
3. 总分写回 `conversation.score` / `article.latestScore`；per-concept 明细另存（第 4 节）。

**最终诊断文案**：用评分员每概念 `note`，加一行总评。总评由代码模板从三维均分推导（`ScoreCalculator.overallDiagnosis`，确定性、不额外调 LLM），不依赖评分员产出散文总评。废弃导师在对话里说 `SCORE:` 与 `parseScore` 正则。

**容错（延续"不静默失败"，对应现有 Bug #1 原则）**：评分员 JSON 坏 / 概念数对不齐 / 调用失败 → 抛错，提示"打分失败，可重试"，不落瞎编的分。

**传输层改动**：现有 `OpenAIClient.send` 未暴露 `temperature`。新增可选 `temperature` 参数（默认不传 = API 默认；评分员传 0）。这是唯一一处动 `AIClient` 协议。

## 第 4 节：数据模型与持久化

`Conversation.score: Int?` 与 `Article.latestScore` 保留语义不变（总分仍写这里）。新增 per-concept 明细：

**新增模型 `ConceptScore`（SwiftData @Model）**

```
concept: String       // 概念名快照（避免 Concept 删除后丢失）
recall:  Int          // 0/1/2
apply:   Int          // 0/1/2
analyze: Int          // 0/1/2
note:    String       // 评分员单概念诊断
conversation: Conversation?   // 反向关系
```

- `Conversation` 加 `@Relationship(deleteRule: .cascade) conceptScores: [ConceptScore]?`，与 `messages` 一致。
- 单概念分、总分都由 0/1/2 现算（纯函数），不存冗余字段，避免与 `score` 不一致。

存明细理由：末尾出分仍需 per-concept 数据来生成"你在 X 概念辨析薄弱"的诊断；将来看历史趋势也有据。低成本高杠杆。

## 第 6 节：错误处理与测试

**错误处理（延续"不静默失败"）**

| 失败点 | 行为 |
|---|---|
| 导师调用失败 / 网络错 | 现有 error banner，对话可重试，不影响已答内容 |
| 控制标记缺失 | 兜底（已纳入实现）：按导师 `.ai` 轮数封顶，达"概念数×4"轮即强制收尾（`quizDone`），防止永远问不完 |
| 评分员 JSON 坏 / 概念数对不齐 | 抛错 → "打分失败，可重试"，不落分 |
| 评分员某项越界（非 0/1/2） | 该项归 0（保守），不整体失败 |
| 评分员被 token 截断 | 复用现有 `responseTruncated` 错误路径 |

**测试（重点压在纯函数与解析层——不依赖网络，可确定性测）**
1. `ScoreCalculator` 单元测试：第 1 节算例（全 2→100、混合→53）写断言；边界（全 0、单概念、概念数为 0）。
2. `ResponseParser.conceptScores` 测试：正常 JSON、带 ``` 包裹、越界值、概念数多/少、空数组、坏 JSON。
3. 控制标记剥离测试：含 `<<NEXT>>`/`<<DONE>>` 的回复 → 正确提取 + 显示文本干净。
4. 一致性回归测试（半自动）：录固定 transcript fixture，对真实评分员跑 5 次，断言总分极差 ≤ 8 分。直接验证目标 #1 的护栏；标记为需 API key 的集成测试，CI 默认跳过。
5. P1 重测：prompt 改了，按 CLAUDE.md 协议重跑概念提取 + 新 quiz 全流程手测，结果记进 CLAUDE.md。

## 未纳入范围（YAGNI）

- 不做流式（SSE）；沿用现状非流式。
- 不做 4 轮上限的可配置化（实测后已改为每概念 1 题，见下）。
- 不为 quiz 单独重新提取概念；复用已展示概念。
- 不做历史分数趋势图表（数据已落盘，留待后续独立功能）。

## 实测调优（2026-05-28，已合并 main）

实现完成、自动化测试全绿后，用户用语音转文字手动实测，暴露了"时长"这一硬伤，做了两轮调整：

1. **第二层追问太长**：原设计「每概念 ≤4 问」在真实语音作答下，15 分钟才考完 2/7 个概念 → 整局约 45 分钟，无法完成。
   - 改为 **每概念恰好 1 题，去掉第二层追问**；轮数封顶从 `概念数×4` 收紧到 `概念数+2`（硬保险，模型话痨也不膨胀）。
2. **1 题导致三维打分变薄**：单题通常只采到复述/举例，辨析维度记 0、分数偏低。
   - 把那 1 题设计成 **单题覆盖三面**：用自己的话解释（复述）+ 举例（举例）+ 为什么重要/与相近概念的区别/失效场景（辨析）。
3. **概念数固定为 3**：配合每概念 1 题 → **总共 3 题**，约 3~7 分钟。

最终形态：**3 个概念 × 1 个三面综合问题**。打分一致性机制（temp-0 评分员 + 代码聚合）不变。一致性带宽的正式测量（`GraderConsistencyTests`，需 key）仍为可选。
